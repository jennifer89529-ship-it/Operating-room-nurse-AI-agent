YOLOv13 手術器械辨識與備物輔助系統設計 30 分鐘逐字稿

建議總長：約 30 分鐘。可依現場提問與展示圖片稍作伸縮。

投影片 1｜開場與題目｜約 1.5 分鐘
各位老師、各位同學大家好。今天我要報告的題目是「YOLOv13 手術器械辨識與備物輔助系統設計」。這個專題的出發點，是我在手術室工作經驗中觀察到，手術備物不只是把器械拿出來而已，而是要確認術式、器械盤、單包器械、數量，以及不同科別的特殊需求。今天我選擇三個術式作為展示，分別是動靜脈血管吻合術，也就是 A-V shunt；人工血管置放術，也就是 Port-A；以及白內障手術 Cataract。這三個術式剛好代表血管外科、一般外科和眼科，也可以呈現不同大小、不同複雜度的器械桌。我的系統不是要取代護理師，而是想用 YOLOv13 影像辨識加上標準器械清單，提供一個術前備物的第二層確認。

投影片 2｜臨床問題｜約 2 分鐘
在臨床現場，手術備物其實有很多容易出錯或需要經驗判斷的地方。第一，不同術式使用的器械盤不一樣，即使是同一科，也可能因醫師習慣或術式變化而有不同組合。第二，很多器械外觀很相似，例如 forceps、clamp、needle holder，對新進人員來說需要時間熟悉。第三，完整器械桌上的器械常常靠得很近，甚至重疊，還會受到反光、角度和拍攝距離影響。所以如果一開始就要求 AI 完全自動辨識每一支器械，短期內很難達到穩定可靠。基於這個現實限制，我把專題定位成「備物輔助」。也就是由 AI 辨識看得清楚的器械，再由標準清單補足完整性，最後仍然保留護理師人工確認。

投影片 3｜研究目標與展示範圍｜約 2 分鐘
本專題的研究目標，是建立一個可以從影像標註、YOLOv13 訓練、術式器械清單整理，到結果比對的完整 prototype。這次我聚焦三個術式。第一個是 A-V shunt，科別是心臟血管外科，對應 A-V Shunt Set，共整理出二十六項器械。第二個是 Port-A，科別是一般外科，對應 Suture Set 加上額外的 towel clip，共十四項器械。第三個是 Cataract，科別是眼科，對應 Phaco Cata Set 加上 Phaco Handpiece Set，共十八項器械。三個術式合計五十八項器械，剛好可以讓我展示不同複雜度的備物情境，而不是只做單一器械辨識。

投影片 4｜整體系統流程｜約 2.5 分鐘
整體流程分為六個階段。第一階段是資料收集，我收集單支器械圖、完整器械桌圖，以及醫院目前的器械明細 Excel。第二階段是影像前處理，單支器械照片先轉成三百乘三百像素，降低尺寸差異；完整器械桌則保留較完整的桌面資訊。第三階段是 YOLO 標註，我製作並修改 YOLO Adjust 工具，讓它可以導入圖片、用滑鼠框選器械、修改 text，並輸出 YOLO labels。第四階段是 YOLOv13 訓練，使用 Ultralytics YOLOv13 做器械類別辨識。第五階段是清單比對，把辨識結果和術式標準器械清單對照。第六階段是報告與開源，將程式、資料結構、README 和 GitHub 上傳說明整理成可公開的專案。

投影片 5｜資料來源與資料集建置｜約 2 分鐘
資料來源主要有三類。第一類是單支器械照片，這些照片用來建立 instrument_yolo_dataset，裡面包含 images、labels、data.yaml、class_names 和 preview。第二類是完整器械桌照片，我把十張術式器械桌整理成 or_table_yolo_dataset，並依照七十、十五、十五的概念分成 train、val、test。第三類是醫院器械明細，我用更正版 Excel 將三個展示術式的對應器械盤整理出來。這裡很重要的是，影像資料和清單資料扮演不同角色：影像負責辨識看得見的器械，清單負責確認術式應該準備哪些器械。兩者結合後，才比較接近臨床備物的需求。

投影片 6｜YOLO Adjust 標註工具｜約 2 分鐘
這張投影片是我這次實作中很重要的一部分：YOLO Adjust 半自動標註工具。原本工具比較偏向截取網頁畫面，但我的需求是放入手術器械照片，所以我把按鈕改成導入圖片，讓使用者可以直接選取本機照片。接著我修正框選功能，讓使用者按下框選學習圖形後，可以在圖片上拖曳，放開滑鼠就新增標註框。因為器械名稱有時需要中英文或臨床慣用名稱，所以我也加入 text 可修改功能。為了降低操作困難，我讓圖片可以自動縮放到視窗內，避免一直滑滾輪。最後工具可以輸出 YOLO label，讓資料能接到後面的 YOLOv13 訓練流程。

投影片 7｜YOLOv13 的角色｜約 2 分鐘
YOLOv13 在本專題中的角色，是做物件偵測，也就是在影像中找出器械位置與類別。我使用的是 Ultralytics 的 YOLO 工具鏈，資料格式是標準 YOLO txt，每一行包含 class id、x center、y center、width 和 height。單支器械影像我先設定為三百乘三百，完整器械桌後續可以使用六百四十乘六百四十或更高解析。訓練指令的概念如投影片所示，例如使用 instrument_yolo_dataset 的 data.yaml，指定 yolov13n.pt，設定 imgsz 和 epochs。這裡我要強調，YOLOv13 不是整個系統的全部，而是辨識模組；真正的備物輔助還需要術式清單比對。

投影片 8｜方法調整：YOLO + 清單比對｜約 2 分鐘
我一開始的想法，是希望在完整器械桌照片中逐支框選，讓 YOLO 自動辨識所有器械。但實作後發現，完整器械桌的器械常常重疊、太小、反光，而且不同器械非常靠近，硬要框完整不但花時間，也會讓標註品質不穩定。所以我調整方法，改成「YOLO 加清單比對」。YOLO 負責辨識看得清楚、外觀明顯的器械；清單比對負責確認這個術式理論上應該有哪些器械。如果 YOLO 沒有辨識到某項必要器械，系統不直接判定錯誤，而是列為待人工確認。這樣比較符合目前資料量和臨床導入初期的可行性。

投影片 9｜三術式清單整理結果｜約 2 分鐘
這張是三個術式整理後的結果。A-V shunt 對應 A-V Shunt Set，共二十六項，其中 forceps 有六項，scissors 和止血鉗各三項，也有 clamp、retractor、needle probe 等。Port-A 對應 Suture Set 加 towel clip，共十四項，主要有 forceps、止血鉗、clamp、needle holder、刀柄和 suction tip。Cataract 對應 Phaco Cata Set 加 Phaco Handpiece Set，共十八項，包含 speculum、micro forceps、scissors、needle holder、handpiece 和 tip 類項目。這五十八項器械形成系統比對基準，也就是報告展示時的標準答案。

投影片 10｜展示一 A-V shunt｜約 2 分鐘
第一個展示是動靜脈血管吻合術 A-V shunt。這個術式屬於心臟血管外科，對應 A-V Shunt Set。它的特點是器械種類比較多，而且有不少血管相關的細長器械，外觀相似度高。對 AI 來說，這是比較有挑戰的場景；對臨床備物來說，這也是很需要清單確認的場景。因此在系統展示上，我會把 A-V shunt 當作複雜度較高的範例。辨識結果如果能抓到部分 forceps、scissors、needle holder 或 clamp，就可以先標為已辨識；其他未被明確辨識的項目，則透過清單列為待確認。

投影片 11｜展示二 Port-A｜約 2 分鐘
第二個展示是人工血管置放術 Port-A。它對應 Suture Set，加上額外 towel clip 五支。這個個案很適合說明「器械盤加單包或追加器械」的情況，因為臨床備物不一定只是一個器械盤，有時還會加上醫師習慣或術式需要的額外器械。系統在整理清單時，會保留這個人工追加來源，讓之後檢查時知道 towel clip 是額外加入，而不是原本 Suture Set 裡的項目。這個術式的器械數量中等，適合做報告中的主要示範流程。

投影片 12｜展示三 Cataract｜約 2 分鐘
第三個展示是白內障手術 Cataract。它對應 Phaco Cata Set 加 Phaco Handpiece Set。眼科器械的特色是小、細、精密，而且有些項目像 handpiece、tip、保護套，從影像上不一定能像剪刀或鑷子那樣容易辨識。所以這個個案可以用來說明本系統的限制與必要性：如果只靠 YOLO，可能會漏掉小型或被遮蔽的項目；但如果加上標準清單，就能知道這些項目仍然需要被人工確認。這也是我把系統定位為半自動輔助，而不是全自動取代的原因。

投影片 13｜執行過程與產出檔案｜約 2 分鐘
這張整理整個執行過程。第一，我完成標註工具，主要檔案是 yolo_adjust_app.py。第二，我建立單支器械資料集 instrument_yolo_dataset，並修正 labels 和 previews。第三，我建立完整器械桌資料集 or_table_yolo_dataset。第四，我把更正版 Excel 整理成 selected_procedure_items.csv，專門保存三個展示術式的五十八項器械。第五，我完成報告資料，包括 PPT、逐字稿、README、PROJECT_SUMMARY、GitHub 上傳指南和 MIT License。這些檔案讓整個專題不只是概念，而是可以被檢查、重現和上傳開源的成果。

投影片 14｜限制與風險控制｜約 2 分鐘
這個專題目前仍有一些限制。第一是影像限制，完整器械桌有重疊、反光、遮蔽和角度問題。第二是資料限制，目前資料量還是 prototype 階段，不能宣稱已經達到臨床準確率。第三是導入限制，院內影像和器械清單涉及資料治理，公開前需要確認授權和去識別化。我的風險控制方式，是把系統定位成輔助提醒，不作為最終判斷；將不確定項目列為待確認；並且在 GitHub 公開版本中以程式碼和資料結構為主，臨床敏感影像另行保護。

投影片 15｜GitHub 開源｜約 2 分鐘
專題內容會整理成 GitHub public repository，建議 repo 名稱是 yolov13-surgical-instrument-assistant。開源內容包含 YOLO Adjust 標註工具、資料集建立腳本、清單整理腳本、data.yaml、class 對照、README、PROJECT_SUMMARY、GitHub 上傳指南和 MIT License。這樣老師或其他同學可以看到我的程式碼、資料流程和訓練設定。需要注意的是，正式公開前如果影像屬於院內資料，應該移除未授權影像，或改成示範資料，只保留可公開的程式、CSV 範例和 YAML 結構。

投影片 16｜結論｜約 2 分鐘
最後總結，本專題完成的是一個從全自動辨識想法，調整成可落地備物輔助的 prototype。我完成了 YOLO Adjust 標註工具、單支器械資料集、完整器械桌資料集、三個展示術式的器械清單，以及 GitHub 開源文件。三個展示術式共整理五十八項必要器械，能作為清單比對的基準。未來如果要繼續發展，可以增加資料量、統一拍攝角度、訓練更穩定的 YOLOv13 模型，並把清單比對結果做成 GUI 的缺漏提醒。我的核心想法是，AI 不需要一開始就取代所有人工流程；只要能提供可靠的第二層確認，就已經有機會降低備物遺漏風險。謝謝大家。
